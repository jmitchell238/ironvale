# Architecture

Ironvale is plain ES modules with no build step. `index.html` loads `js/app/main.js`, which imports everything else. The game draws to a 960×540 canvas in landscape, or a 540-wide canvas as tall as the screen in portrait (`setViewSize` in `js/config/index.js`; `W`, `H` and `CONTROLS` update when the phone turns). Either way it is letterboxed to fit.

## Layers

```
app/main.js        DOM, screens, the animation loop
   ↓
adapters/          Rendering, input, sprites, audio, saving
   ↓
world/             GameSession and its systems: the state of the current run
   ↓
domain/            Game rules as pure functions: no DOM, no globals
   ↓
config/, core/     Tuning numbers and math helpers
```

Each layer only imports from the layers below it. `domain/` never imports from `world/`, `adapters/` or `app/`, which is what lets the tests run the rules in Node without a browser.

## GameSession

`GameSession` is the only thing that changes run state. The app creates one, passing in the audio and save adapters (the tests pass stand-ins), and calls `update()` once per frame:

```js
const session = new GameSession({ audio, save });
session.loadLevel('forgegate-fields');
session.update(dt, { x, y, jump, attack });
```

The work is done by the modules in `world/systems/`, which receive the session. They call into `domain/` for the actual rules.

Useful fields:

- `session.screen`: `menu`, `select`, `play`, `levelup`, `allocate`, `clear` or `over`
- `session.levelPhase`: `explore`, `boss` or `done`
- `session.meta`: saved progress (`xp`, `level`, `unspentPoints`, `stats`, `levelUnlocked`, `ngPlus`, `campaignCleared`)

## Screens

```
menu → select → play ──(die)──→ over → continue from checkpoint, or retry
                  │
                  └──(clear stage)──→ allocate (if you have points) → clear → next stage or menu
```

Leveling up during a stage only banks a point. Points are spent on the `allocate` screen between stages.

## Stages

Stages are plain objects in `js/domain/levels.js`. Each has bounds, a spawn point, platforms, ladders, encounters, checkpoints, a gate, and optionally a boss. An encounter is a trigger X position plus a list of enemies to spawn when the player passes it. The gate opens once every encounter has fired and no enemies are left. On a stage with a boss, the boss spawns in an arena past the gate.

All four stages (Forgegate Fields, Forest Ramparts, Forge Ruins and Iron Caverns) are tile-map stages. Each is drawn on a 32 px grid with a few builder calls (`groundCells`, `fillCells`, ladders, coins, stamps), and `compileTileMap()` turns the grid into:

- **platforms**: the top of every ground run, plus one-way stone ledges, bridges and floating islands
- **solids**: rectangles that block the player and enemies from the sides and from below
- **tiles**: the grid itself, which `renderStage.js` reads to choose tops, edges and fill for each cell. The map's `theme` picks the tileset, tile rules and parallax background (`THEMES` in `renderStage.js`) and the scenery stamps (`STAMPS` in `levels.js`)

The stage's solids are merged with the locked gate into `session.blockers` each frame. Falling below `bounds.fallY` costs a heart and returns the player to the last solid ground they stood on; enemies knocked off a cliff count as kills.

A stage without `tiles` would fall back to the older block-out drawing in `render.js`; no stage uses it now.

The boss arena is part of the map: on every stage the gate is the arena's left wall, the arena is a flat, walled floor one screen wide (`boss.arenaMinX` to `arenaMaxX`, which also bounds the player and camera while the boss lives), and the boss spawns on it. Stage 1's arena holds the Nightmare, stage 2's the Hell Beast, stage 3's the angel (she spawns in the air; `boss.floorY` is where she lands, and `boss.camY` holds the camera up so her wings stay in view) and the throne room the Warden. The Warden is drawn from three strips (`enemy/warden`, `_windup`, `_slam`) picked from its slam state in `drawEnemy`, so the art follows the telegraph timings; the other bosses do the same from their own state fields (`nightmareFrame()`, `beastFrame()`, `angelFrame()`).

## Bosses

An enemy with `bossAi` hurts only through its own moves, which come back from `aiUpdateEnemy()` in the same shape as the Warden's slam (`{ hit, damage, knockback, dir }`) so the enemy system needs no special case. The shared fields are `bossState` (`idle`, `windup`, the attack, `recover`), `bossMove`, `bossT` and `bossCd`; the angel keeps her `swoopState` fields. The wind-up is the warning and nothing interrupts it (a hit still does damage). A `vis` field (0 to 1) lets the Hell Beast sink into the ground: below 0.3 it sets `untargetable`, which `resolveMeleeHits()` skips.

## Enemy names

The enemy type ids are older than the art. In code they are still `goblin`, `bat` and `shield_skeleton`; on screen they are a skeleton, a ghost and a Bone Guard. `wolf` and `iron_warden` match. `spider`, `thing`, `burning_ghoul` and `hell_hound` are the new ones; the hound is the only enemy with a leap (`ENEMY_LUNGE` in the config, `tickEnemyLunge()` in `enemyAi.js`).

The wizard (`wizard`, `ENEMY_CAST`, `tickEnemyCast()`) and the fire skull (`fire_skull`, `ENEMY_SWOOP`, `tickEnemySwoop()`) follow the same pattern: a state machine in `enemyAi.js` whose wind-up is the warning and which a hit cancels, with the strip chosen in `render.js` (`wizardFrame()`, `skullFrame()`).

## Enemy projectiles

`domain/projectiles.js` holds shots in flight as plain objects (`makeProjectile(kind, ...)`, kinds in `ENEMY_PROJECTILES`). `tickProjectiles()` moves them and reports the ones that end: `hit` (the knight, only when not in i-frames, so a shot never hurts twice), `wall` (a stage solid), `out` (stage bounds) or `expired`. `cutProjectiles()` removes the ones inside the sword's box. `world/systems/projectiles.js` runs them each frame from `GameSession.update()`, calls `hurtPlayer()` with the shot's damage (already scaled by New Game+ when the enemy spawned) and drops the list on `loadLevel()` and `endRun()`. An enemy fires by setting `e.shot` to a new projectile, or an array of them for a volley; the enemy system spawns them. A shot with `g` (gravity) flies in an arc, which is how the Hell Beast lobs three fireballs, and the Fallen Angel's bolts use their own kind (`lightbolt`). `drawProjectiles()` in `renderStage.js` draws them.

## Body, sword and drawing are separate

These are tuned independently, and the "sword ≠ body" tests in `tests/run.mjs` make sure they stay that way:

| To change | Edit | Doesn't affect |
|-----------|------|----------------|
| Sword length | `PLAYER_SWORD.attackRange` | Collision box |
| Collision box | `PLAYER_BODY.w` / `h` | Sword range |
| Swing speed, attack buffer, combo | `PLAYER_SWORD.attackTime`, `attackCooldown`, `attackBuffer`, `comboWindow`, `comboFinisherMul` | Movement |
| How big the knight looks | `PLAYER_DRAW.drawScale` | Physics or hitboxes |
| Jump feel | `PLAYER_MOVE` and `domain/player.js` | Combat |
| Enemy ledge behavior | `ENEMY_AI` and `domain/enemyAi.js` | The sword |
